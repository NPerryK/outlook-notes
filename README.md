# CDF Updater — תוסף Excel

תוסף שמוסיף לאקסל לשונית **CDF** עם חלונית צד שעושה ארבעה דברים:

1. **ייבוא קבצים** — `CDF_List_Export` מחליף את הגיליון **GCC**, ו-`650` מחליף את הגיליון **Mantra**. כל קובץ **מוחק ומחליף** את הגיליון שלו בקובץ הגדול (באותו מיקום).
2. **הרצת האלגוריתם** — אלגוריתם ה-CDF (`CDF_Algorithm_2026-11-05`) מומש כקוד (`cdf-algo.js`), בשלבים. לוחצים **Check changes**, רואים כל תא שישתנה (לפני → אחרי, ולפי איזה כלל), את **Cross-check**, ואז **Apply**.
3. **שורה חדשה לחריג** — Claude קורא את PDF החריג ואת PDF ה-ATT (כולל התמונות) וממלא את השדות, ואתה עובר על הטופס ומאשר. הכל דרך מנוי Claude שלך, בלי עלות נוספת.
4. **שליחת מייל** — בוחרים מה לשלוח ולמי, ונפתחת טיוטה מוכנה ב-Outlook.

כל פעולה נרשמת בגיליון **UPDATE LOG** עם הערך הקודם והחדש של כל תא, וגם רשימת CDF שהופיעו בקובץ העדכון ולא נמצאו בבסיס.

החלונית מחולקת לארבעה מסכים (המקשים מתחת לתצוגה הכהה): **TODAY** — ייבוא, בדיקה והחלה; **NEW ROWS** — שורות חדשות; **EMAIL** — מיילים; **SETUP** — ביטול, הגדרות, מראה וקובץ הכללים. נקודה כתומה על מקש אומרת שמשהו מחכה שם (למשל מייל מוכן).

> שלבים 1, 2 ו-4 לא מוציאים נתונים מהמחשב. בשלב 3 אתה מעלה את קבצי ה-PDF ל-claude.ai בעצמך. כדאי לוודא מול אבטחת מידע שזה מותר לסוג המסמכים האלה.

## התקנה (פעם אחת, כ-10 דקות)

### שלב 1 — manifest.xml (כבר מוכן)
`manifest.xml` כבר מוכן לחשבון GitHub ‏**NPerryK** (כתובת: `https://nperryk.github.io/cdf-updater/`). אין צורך לערוך אותו — רק לוודא שהמאגר נקרא בדיוק `cdf-updater`.

### שלב 2 — העלאה ל-GitHub ופרסום ב-Pages
1. ב-github.com: **New repository** ← שם: `cdf-updater` ← **Public** ← **Create repository**.
   (GitHub Pages בחשבון חינמי עובד רק עם מאגר ציבורי. במאגר יש רק קוד וכללים — אף פעם לא להעלות אליו קבצי נתונים.)
2. לחץ **uploading an existing file**, גרור פנימה את **כל** הקבצים והתיקיות (`assets`, `lib`, `tests` וכל השאר) ← **Commit changes**.
3. **Settings ← Pages** ← Source: **Deploy from a branch** ← Branch: **main**, תיקייה **/ (root)** ← **Save**.
4. אחרי 1–2 דקות פתח בדפדפן:
   `https://nperryk.github.io/cdf-updater/taskpane.html`
   אמורה להופיע החלונית עם הודעה "Opened outside Excel" ונורית ירוקה **RULES OK** בראש החלונית. אם כן — האירוח עובד.

### שלב 3 — התקנה באקסל

**Excel למחשב (Windows)** — דרך תיקייה משותפת:
1. צור תיקייה (למשל `C:\AddinCatalog`), שים בה את `manifest.xml` המעודכן.
2. קליק ימני על התיקייה ← **Properties ← Sharing ← Share** ← **Share**. העתק את הנתיב שמופיע (נראה כמו `\\שם-המחשב\AddinCatalog`).
3. באקסל: **File ← Options ← Trust Center ← Trust Center Settings ← Trusted Add-in Catalogs**.
4. הדבק את הנתיב ב-**Catalog Url** ← **Add catalog** ← סמן **Show in Menu** ← OK ← OK.
5. **סגור ופתח את אקסל מחדש.**
6. **Home ← Add-ins ← Advanced** ← בחלון למעלה **SHARED FOLDER** ← בחר **CDF Updater** ← **Add**.
7. תופיע לשונית **CDF** בסרגל ← **Open Updater**.

**Excel באינטרנט** — **Home ← Add-ins ← Advanced** ← בתפריט למעלה מימין **Manage my add-ins ← Upload My Add-in** ← בחר את `manifest.xml`.

> אם "Trusted Add-in Catalogs" נעול אצלכם (מדיניות ארגונית), צריך לבקש מ-IT לפרוס את `manifest.xml` דרך Microsoft 365 admin center (Integrated apps).

## שימוש

### כל בוקר: Morning update
1. פתח את הקובץ הגדול (`CDF REQ STATUS AC 1 - 01574`) ← לשונית **CDF ← Open Updater**. החלונית נפתחת במסך **TODAY**.
2. גרור את `CDF_List_Export` ואת `650` לכרטיס **Morning update** (או לחץ על כל שורה ובחר קובץ).
3. לחץ **Run morning update**. התוסף עושה לבד, לפי הסדר:
   1. **Check the files** — בודק כל קובץ לפני הייבוא (ראה "בדיקת קבצים" למטה).
   2. **Replace the sheets** — מחליף את GCC ו-Mantra.
   3. **Check changes** — מריץ את האלגוריתם ואת בדיקות הבקרה.
   4. **Apply** — כותב את השינויים ורושם אותם ב-UPDATE LOG.
   5. **Prepare the daily email** — מכין את המייל היומי, ומקש **EMAIL** מקבל נקודה. **Open the daily email** מעביר אליו.
4. בלי קבצים חדשים הכפתור נקרא **Run morning update (no new files)** — הוא מדלג על הייבוא ומריץ את השאר על הגיליונות הקיימים.

**מתי הוא עוצר ומחכה לך** (כתום = הערה, אדום = עצירה):
- קובץ שנראה לא תקין: אין בו שורות, יש בו הרבה פחות שורות מהגיליון הנוכחי (יותר מ-10%), חסרות בו עמודות, או שם הקובץ לא מתאים.
- בדיקת בקרה שנכשלה, או שגיאה באלגוריתם.
- יותר מ-40 תאים שישתנו (יותר מהרגיל).
- פחות CDFs ב-GCC מבהרצה הקודמת, או CDF שנעלם מ-GCC מאז ההרצה הקודמת.

בעצירה מופיעה הסיבה ושני כפתורים: **Continue anyway** (ממשיך מאותה נקודה) או **Stop here** (שום דבר נוסף לא משתנה). אם הוא עצר לפני ההחלפה — הגיליונות נשארים כמו שהיו.

### בדיקת קבצים לפני ייבוא
כשבוחרים קובץ (בכרטיס הבוקר או בשלב 1), התוסף קורא אותו ומשווה לגיליון שהוא עומד להחליף, ומציג מתחת לשם הקובץ:
- ירוק — `1001 data rows (now 1001), columns match.`
- כתום — הקובץ נשמר לפני יותר מיום ("is it today's export?"), כמה שורות פחות, או שם קובץ אחר מהצפוי.
- אדום — אין שורות נתונים, הרבה פחות שורות, או עמודות חסרות (עם שמות העמודות).

### צעד אחר צעד (כמו קודם)
מתחת לכרטיס הבוקר, תחת **or step by step**:
1. **שלב 1:** גרור את שני הקבצים ← **Replace sheets** ← **Yes, replace**.
2. **שלב 2:** **Check changes** ← עבור על השינויים ועל **Cross-check** ← **Apply N changes**.

### מה רואים אחרי Check changes
- **שורת מסקנה** בראש: "Nothing to update", ‏"Δ 3 cells to update in 2 CDFs", או עצירה — עם מצב בדיקות הבקרה.
- **Changes by CDF** — כרטיס לכל CDF עם השורה שלו, וכל תא: עמודה, לפני (אדום) → אחרי (ירוק), ומספר הכלל. כפתורי הסינון מעל (`S 1`, `T 2`, `rule 20.2 3`) מציגים רק עמודה אחת או רק כלל אחד; לחיצה נוספת מבטלת.
- **Cross-check** — סגור כברירת מחדל, עם שורת סיכום ("Control totals 3/3 OK, CDF SUMMARY 6/6 the same"). לחיצה פותחת את הפירוט.
- **סרגל הפעולה** בתחתית החלונית מציג את הפעולה הבאה של המסך (Check changes / Apply / Open draft in Outlook), כדי שלא צריך לגלול אליה. כשהכפתור האמיתי כבר על המסך, הסרגל מסתיר את עצמו.

### התצוגה הכהה למעלה (today at a glance)
אחרי כל בדיקה או החלה מופיעים: **OPEN**, ‏**CONV ENG**, ‏**FINAL APPR**, ‏**TO SIGN** (בטבלאות ה-Pending), ‏**RELEASED**, עם חץ ▲/▼ ומספר — כמה השתנה מאז ההרצה הקודמת (שמופיעה ב-**SINCE**). מתחת: פסים לפי תחנה, וקו מגמה של ה-Open (מההרצה השנייה ואילך).
המספרים נשמרים **בתוך החוברת** (לא בגיליון — בחלק XML נסתר של הקובץ), אז הם עוברים עם הקובץ ונשמרים כשהוא נשמר (Ctrl+S). נשמרות עד 60 הרצות.

**כל מספר לחיץ:** לחיצה על מספר (OPEN, ‏CONV ENG, ‏FINAL APPR, ‏TO SIGN, ‏RELEASED) או על פס של תחנה פותחת את רשימת ה-CDFs שמאחוריו, מהארוך ביותר בתחנה לקצר. לחיצה על שורה פותחת את ה-CDF ומסמנת את השורה שלו. אם ברשימה יש CDF שלא נמצא ב-GCC (ולכן לא נספר במספר שעל המסך), זה כתוב בראש הרשימה.

**ימים בתחנה:** מכל עדכון התוסף זוכר באיזו תחנה כל CDF פתוח נמצא ומאיזה יום (בחלק נסתר של החוברת). CDF שעובר תחנה מקבל תאריך מדויק. ל-CDF שהתוסף עוד לא ראה עובר תחנה, התאריך נלקח משינוי של עמודה S ב-UPDATE LOG אם יש, ואם אין — כתוב "open N d" (מספר הימים מאז שנפתח, כי היום שהגיע לתחנה לא ידוע), או "N+ d" (לפחות N ימים — מאז שהתוסף ראה אותו שם לראשונה).
כש-CDFs נמצאים 14 יום או יותר באותה תחנה, מופיעה למטה בתצוגה נורית כתומה, למשל **5 CDFS 14+ DAYS AT STATION**, ולחיצה עליה פותחת את הרשימה. בהתחלה מופיע "DAYS AT STATION — TRACKING SINCE dd/mm", והנורית מתמלאת עם הזמן.

### חיפוש CDF
**🔍** בראש החלונית, או **Ctrl+F** כשהחלונית בפוקוס. כותבים מספר (`961`, ‏`740.A`, ‏`CDF 740.A`) או מספר מלא (`A330-1-961.-`) ← Enter.

מופיעים: סטטוס, תחנה, מי בעמדת החתימה, **מסלול** (INIT → POC → ENG → F/A → REL, עם התחנה הנוכחית מוארת ומספר הימים בה), התיאור, שדות השורה, שורות הפתרון עם סטטוס Mantra, השורה ב-GCC, וההיסטוריה של ה-CDF מ-UPDATE LOG (החדש ראשון). **Go to row** מסמן את השורה בגיליון CDF. מספר שלא נמצא מציע מספרים קרובים. Esc סוגר.

**הדבקה:** מעתיקים מספר CDF מכל מקום — ממייל, מ-My Notes (כפתור ההעתקה בכרטיס), מגיליון — לוחצים במקום ריק בחלונית ו-**Ctrl+V**. החיפוש נפתח על ה-CDF והשורה שלו מסומנת בגיליון CDF מיד. אם הודבקו כמה מספרים, השאר מופיעים תחת "Also pasted" ולחיצה על כל אחד מסמנת את השורה שלו. הדבקה בתיבות טקסט עובדת כרגיל.

### ביטול העדכון האחרון (Undo)
**SETUP ← Check what can be undone** (או **Undo this update** מיד אחרי החלה).
- התוסף קורא מ-UPDATE LOG את ההחלה האחרונה ומראה כמה תאים אפשר להחזיר.
- תא ששונה שוב מאז (ביד או בהרצה אחרת) **לא נדרס** — הוא מופיע ברשימה עם הערך הנוכחי ומה שההחלה כתבה.
- **Undo N cells** מחזיר את הערכים הקודמים ורושם את הביטול ב-UPDATE LOG (‏`Undo of <id>`). ביטול שני לא מבטל שוב את אותה החלה.
- שורות פתרון ששלב 2 הוסיף או הסיר חוזרות למצבן (**Undo N cells and M row changes**). שורה ששונתה מאז נשארת.
- שורות חדשות (NEW ROWS) לא מבוטלות כך — מוחקים אותן ביד.

> מומלץ לשמור את הקובץ לפני "החל" — לא בטוח ש-Ctrl+Z יבטל שינויים שתוסף כתב.

## הגדרות בתוך החוברת (שמות אנשים)
המאגר ב-GitHub ציבורי, ולכן שמות אנשים לא צריכים להיות ב-`rules.txt`. **SETUP ← Workbook settings**:
1. **Copy the settings lines from rules.txt** — מעתיק לתיבה את שורות ההגדרות (STATION, SUPPLIER, FINAL_APPROVAL_RELEASE, PENDING_TABLE, DUPLICATE_CDF, EMAIL_GROUP, CLAUDE_PROJECT).
2. **Save to workbook** ← שמור את הקובץ (**Ctrl+S**).
3. רק אחרי זה: מחק את השורות האלה מ-`rules.txt` ב-GitHub.

- שורות בחוברת **מתווספות** ל-`rules.txt` ו**גוברות** עליו (למשל PENDING_TABLE בחוברת מחליף את זה שבקובץ).
- מותר בתיבה רק: STATION, SUPPLIER, FINAL_APPROVAL_RELEASE, PENDING_TABLE, DUPLICATE_CDF, PERSON_GROUP, PERSON_ALIAS, EMAIL_GROUP, CLAUDE_PROJECT, REPORT. שורה אחרת נדחית עם מספר השורה.
- **רשימת האנשים לעמודה V (שלב 2)** — שורות `PERSON_GROUP` (קבוצה ← שמות מופרדים ב-`;`) ו-`PERSON_ALIAS`. מדביקים אותן כאן ושומרים. רשימה בחוברת מחליפה רשימה שב-`rules.txt` (שם לא אמורה להיות רשימה — אלה שמות אמיתיים).
- ההגדרות נשמרות בחלק XML נסתר של החוברת, כמו ההיסטוריה — לא בגיליון ולא במחשב. מי שפותח עותק של הקובץ מקבל אותן.
- אם יש שגיאה בהגדרות בחוברת, הנורית **RULES** נהיית אדומה ו-SETUP מראה `Workbook settings, line N: ...`.

> **מגרסה 1.9.2** `rules.txt` כבר לא כולל את FINAL_APPROVAL_RELEASE ואת PENDING_TABLE (הם שמות של אנשים). הם חייבים להיות בהגדרות שבחוברת: בלעדיהם הנורית **RULES** אדומה, SETUP כותב `Workbook settings: The workbook settings need FINAL_APPROVAL_RELEASE (rule 10) and PENDING_TABLE (100.5)…`, ו-Check changes מחכה. מדביקים את השורות (בקובץ הפרטי שקיבלת) ב-Workbook settings → Save to workbook → Ctrl+S.

## קישור ל-My Notes (Outlook)
שני התוספים מדברים זה עם זה בהעתקה והדבקה. שום דבר לא עובר דרך GitHub או שרת.

**השגרה היומית — הדבקה אחת לכל כיוון:**
1. באקסל, בסוף ה-Morning update: **Copy for My Notes**.
2. ב-Outlook: פותחים את My Notes על מייל כלשהו, לוחצים במקום ריק ו-**Ctrl+V**. הסטטוס נקרא, **ו-My Notes מעתיק מיד את ההערות שלך בחזרה**.
3. באקסל: לוחצים במקום ריק בחלונית ו-**Ctrl+V**. ההערות נקראות ונשמרות בחוברת.

(אפשר גם דרך התיבות: ב-My Notes ‏**Reports ← CDF status (Excel)**, ובאקסל **SETUP ← Link with My Notes**.)

**מאקסל ל-Outlook — הסטטוס של כל CDF:**
- כל מייל שמוזכר בו CDF — בנושא, בגוף, בשם קובץ מצורף, ב-Label או בהערה — מציג למעלה כרטיס: סטטוס, **מסלול** (אותה תמונה כמו באקסל) וימים בתחנה, מי בעמדת החתימה, ספק, שם השרטוט, המסמכים עם הסטטוס שלהם ב-Mantra, ו-"Ready for … to sign" אם ה-CDF בטבלת Pending.
- יותר משני CDFs במייל: הראשון מוצג במלואו, השאר בשורה אחת כל אחד (סטטוס, מסלול מוקטן, ימים), ולחיצה פותחת.
- **+ Follow-up** ליד כל CDF: התיבה מתמלאת ב-"CDF 961: " ותאריך יעד בעוד 3 ימי עבודה.
- סימון **"2 open notes"** ליד CDF שיש עליו הערות פתוחות (בכל המיילים).
- הערה פתוחה על CDF ששוחרר: הכרטיס כותב "CDF 004 was released. Your note … is still open" עם **Mark done**.
- **מיילים שהתוסף באקסל הכין** (לספק: "Open CDFs at Conversion Engineer — ANN/SIE", או "CDFs ready for your signature — Dana Ben-Ari"): My Notes מציע **Add follow-up** — הערת Awaiting Reply עם תאריך בעוד 3 ימי עבודה ורשימת ה-CDFs מהמייל. אם לא הגיעה תשובה עד אז, היא מופיעה כ-due גם ב-My Notes וגם בסוף ה-Morning update באקסל.
- התוסף מזהה `A330-1-961.-`, ‏`A330-1-740.A`, ‏`CDF 740.A`, ‏`CDF#961`, ‏`CDF-052`. מספר בלי גרסה מציג את כל הגרסאות שלו.
- סטטוס בן יום או יותר מסומן בכתום ("paste today's status").
- מספר שלא קיים בגיליון מופיע כ-"Not in the CDF sheet".

**מ-Outlook לאקסל — ההערות שלך:**
1. ב-My Notes: **Reports ← CDF status (Excel) ← Copy notes for CDF Updater**.
2. באקסל: **SETUP ← Link with My Notes** ← לוחצים בתיבה ← **Ctrl+V**. ההערות נשמרות בחוברת.

### לאן נכנס כל CDF
- **כבר קיים בעמודה C:** השורה שלו מתעדכנת.
- **יש לו שורה מוכנה:** בעמודה B כבר כתוב המספר שלו, עם הקישורים ל-PDF, ו-C ריקה. הוא נכנס לשורה הזו, והקישורים ב-A וב-B לא נוגעים.
- **רביזיה (.A, .B):** נוספת שורה חדשה מיד אחרי ה-CDF המקורי ושורות הפתרון שלו, כמו שעושים היום ידנית.
- **אף אחד מאלה:** שורה חדשה בסוף, ובטופס מופיעה אזהרה.

העמודות שנכתבות לפי הכותרות בגיליון CDF:

| עמודה | כותרת | מה נכתב |
|---|---|---|
| C | LINK TO GCC | מספר ה-CDF כפי שמודפס, למשל `A330-1-973.-` |
| D | CDF REVISION | `-` או אות הרביזיה |
| F | RECEIVED DATE | התאריך של היום |
| G–L | PRIORITY … NRC | מהטופס |
| M | CDF DWG REV | רביזיית השרטוט |
| N | AUTHOR | שם, וטלפון בשורה שנייה |
| O | TECHNICAL ADVISER | שם, וטלפון בשורה שנייה |

### כמה CDFs בתשובה אחת
מופיעה רשימה של כל ה-CDFs, ולכל אחד:
- היעד: **Row N (prepared)** או **New row N** (כחול), **Updates row N** (כתום, ה-CDF כבר קיים בקובץ), או **New row N, after …** (ירוק, רביזיה שנכנסת אחרי ה-CDF המקורי).
- תחילת התיאור, ונקודות לבדיקה מסומנות בכתום.
- תיבת סימון. מה שלא מסומן לא נכתב.

ואז אחת משתיים:
- **Write N rows** — כותב את כל המסומנים בפעולה אחת, וכל תא נרשם ב-UPDATE LOG.
- **Check one by one** — טופס מלא לכל CDF, עם אפשרות לתקן לפני הכתיבה: "CDF 1 of 3" ← **Add row** או **Skip**.

**הטופס:**
- ליד כל שדה רואים את **אות העמודה ואת שם הכותרת שלה בקובץ**. כך מיד רואים אם שדה הולך לעמודה הלא נכונה.
- "לבדוק" — דברים ש-Claude לא היה בטוח בהם.
- אם ה-CDF כבר קיים בקובץ, כתוב באיזו שורה, וערכים קיימים שיוחלפו מסומנים.
- אם Claude לא ראה את שמות הקבצים, שדות הקישור ריקים — אפשר להקליד בהם את שם הקובץ.
- מתקנים מה שצריך ← **Add row**. שדה ריק לא נכתב ולא מוחק ערך קיים.

**התאמה:**
- את המיפוי של שדה ← עמודה קובעים בשורות `NEWROW` ב-`rules.txt`. הוא מותאם לכותרות של גיליון CDF (הטבלה למעלה). אם תשנה עמודות בגיליון, עדכן גם אותו.
- הנוסח ש-Claude מקבל (סגנון התיאור, מה לסמן לבדיקה) נמצא ב-`ai-prompt.txt`. אפשר לערוך אותו ב-GitHub כמו את הכללים.
- קישורים: `NEWROW A = LINK ATT "..\PDF\"` כותב בעמודה A קישור לתיקייה + שם הקובץ. נתיב יחסי (כמו `..\PDF\`) נמדד מהתיקייה של קובץ האקסל.

### שלב 2 — Mantra → CDF

רץ אוטומטית אחרי שלב 1, באותה לחיצה על **Check changes**, כשבחוברת יש גיליון **Mantra** וגיליון **MANTRAREV**. הוא קורא את גיליון CDF כמו ששלב 1 משאיר אותו, ושני השלבים הם עדכון אחד (Apply אחד, יומן אחד, Undo אחד).

- **AA / AB** — המסמכים מתשובת GCC (עמודה S) והרוויזיה הגבוהה ב-Mantra. זיהוי לפי 25: התאמה מדויקת; התיקונים המאושרים (25.5); מספר H שנכתב בלי האותיות שלו או בלי ‎-101; ספרת ATA אחת שגויה כשיש מועמד אחד והשרטוט (J) לא סותר; מסמך שקיים רק ב-MANTRAREV (משוחרר, בלי חתימות מומצאות). אין ניחוש — מה שלא חד-משמעי נכתב **CHECK SOLUTION** ומופיע ברשימת "to check".

- **שורות פתרון (110)** — שורה לכל מסמך. CDF שקיבל יותר מסמכים מקבל שורות שלמות מתחת לבלוק שלו: עמודות A:P ו-Y:Z ממוזגות עם העוגן, ו-E, H, O, R, S, T, AC:AH מפנות אליו (`=IF($R$907="","",$R$907)`), כמו שהמאקרו בונה. CDF עם פחות מסמכים מאבד את שורות ההמשך העודפות — רק שורות שזוהו כהמשך שלו. הכול מלמטה למעלה, ולפני שמשהו זז נבדק כל בלוק; בדיקה אחת שנכשלת עוצרת את כל הכתיבה. אם על גיליון CDF יש סינון פעיל, התוסף מבקש לנקות אותו קודם (אי אפשר למזג שורות מעל שורות מוסתרות) ולא כותב כלום.
- בחלונית: כרטיס **Mantra** עם גודל הקטלוג, סוגי הבלוקים, וכל CDF שמשנה שורות (`+3 A330-1-701.- · new rows 908–910`). מספרי השורות בכרטיסים הם המספרים **אחרי** הוספת השורות.
- **Undo** מחזיר את התאים, מוחק את השורות שנוספו ומחזיר שורות שהוסרו (עם הערכים שלהן מהיומן). שורה שמישהו שינה מאז נשארת כמו שהיא.
- **הבוקר האוטומטי** לא עוצר בגלל מאות תאים מ-Mantra (יום רגיל); הוא עוצר כשיש פתרון לבדיקה, כשיש שורות להסרה, או כשגיליון Mantra לא קריא.
- נבדק מול הרצת המאקרו של 05/11 (RUN-20261105055714): מאותה נקודת התחלה, גיליון CDF שיוצא זהה למה שהמאקרו השאיר — כל התאים ב-C, Q, R, S, T, U:X, AA, AB בכל 2,278 השורות, כולל 5 השורות החדשות (701 ‏+3, ‏881.A ‏+1, ‏921 ‏+1), המיזוגים והנוסחאות שלהן.

### שלב 3 — CDF SUMMARY ו-EMAIL DRAFT

רץ באותה לחיצה על **Check changes**, אחרי שלבים 1 ו-2. הוא בונה את שני הגיליונות מגיליון CDF **כמו שהעדכון משאיר אותו** (בזיכרון, לפני שנכתב משהו), ומשווה למה שיש בהם עכשיו. Apply כותב אותם יחד עם שאר העדכון. אם רק הם השתנו (למשל יום חדש — תאריך חדש במייל), הכפתור הוא **Rebuild**.

- **CDF SUMMARY — כל הטבלאות לפי 100:** CDF STATUS, GCC CURRENT STATUS, GCC SIGNATURE POSITION + MOR + IGOR (זו לצד זו), WHERE ARE THE CDFS, MANTRA SIGNATURE POSITION, MANTRA WHO, PERSON GROUP / DEPARTMENT, REJECTED (עם REJECTED CDFS / DOCUMENTS), ו-PERSONS – GROUP – SIGNATURE – CDF – PENDING MANTRA DOCUMENTS.
  - רק חריגי Open, ומסמכים שלא שוחררו (100.2.1). ספירה לפי צמדי מסמך–רוויזיה, אדם–חריג, כמו בכל טבלה.
  - הנוסחאות הן הנוסחאות של המאקרו (COUNTIFS על CDF, ‏SUM, ‏COUNTA, ‏SUMPRODUCT) — הטבלאות מתעדכנות לבד כשמשנים את CDF. טבלאות Mantra נכתבות כערכים.
  - עיצוב לפי 100.1: כותרות אדומות `#B10001` עם טקסט לבן מודגש, גוף לבן, Calibri 10, גבול דק `#BCBCBC` סביב כל תא, רוחבי עמודות, ומיזוגים בטבלת האנשים (A, B, C לכל אדם).

## עריכת הכללים (rules.txt)

2. קובץ שהוסר מהגרסה החדשה לא נמחק לבד: לחץ עליו במאגר ← **⋯** ← **Delete file** ← **Commit changes**.
3. חכה 1–2 דקות, ואז סגור ופתח את החלונית באקסל.

לא צריך לגעת בהגדרות Pages ולא להתקין מחדש באקסל. יוצא דופן אחד: אם `manifest.xml` השתנה (שם הכפתור, הלשונית, הכתובת), צריך להחליף גם את העותק בתיקייה המשותפת, ולהסיר ולהוסיף מחדש את התוסף באקסל.
אם אחרי סגירה ופתיחה של אקסל עדיין רואים את הגרסה הישנה, סגור את אקסל ומחק את התוכן של התיקייה `%LOCALAPPDATA%\Microsoft\Office\16.0\Wef\`. ייתכן שזה ימחק גם את מה שנשמר בחלונית עצמה (קישור ה-Project וקבוצות המייל). לכן כדאי לרשום את הקישור ל-Project גם ב-`rules.txt` (`CLAUDE_PROJECT`).

## יעילות (1.9.2)
אותן תוצאות, פחות המתנה:
- **פחות נסיעות ל-Excel.** כל `ctx.sync` הוא נסיעה הלוך-חזור ל-Excel, והיא שעולה זמן. Check changes קורא עכשיו את כל הגיליונות יחד — אילו קיימים (נסיעה אחת), הטווחים שלהם (אחת), השורות בקבוצות של עד 150,000 תאים, ושתי נסיעות ל-BACKUPDATA. על החוברת של 05/11: **31 → 9** נסיעות ב-Check, **75 → 41** ב-Apply. גם הכתיבה ל-BACKUPDATA והקיצוץ מקובצים.
- **פורמטים רק איפה שצריך.** פורמט המספרים נקרא רק מגיליון CDF (בשביל תאריכי הסגירה). את MANTRAREV (כ-13,000 שורות) קוראים בלי הפורמטים.
- **פחות חישוב.** ההמרה לשעון ישראל יוצרת פורמטר אחד, ולא אחד לכל תאריך, ושומרת את ההפרש לכל שעה. Mantra נקרא פעם אחת לשלבים 2 ו-4. מזהי המסמכים מפורקים פעם אחת, והמועמדים לתיקון (25.6) מקובצים מראש. על הנתונים של 05/11 החישוב ירד מכ-720 לכ-200 מילישניות (פי 3.5).
- **אותה תוצאה — נבדק:** הגרסה הישנה (1.9.1) והחדשה הורצו על אותם קלטים — הנתונים של 05/11 (בשלוש תצורות של BACKUPDATA) ו-260 גרסאות שלהם עם שינויים אקראיים (סטטוסים ב-GCC וב-Mantra, תאריכים, רוויזיות, מזהים עם טעות הקלדה, שורות שנמחקו, שעות סביב מעבר שעון) — וכל התוצאות זהות עד התו. בנוסף, החוברת כולה (ערכים, פורמטים, נוסחאות, מיזוגים, עיצוב, סדר גיליונות) זהה אחרי כל צעד של שישה תרחישים, כל אחד פעמיים ובשתי שעות שונות, וההמרה לשעון ישראל זהה על 1.3 מיליון רגעים בין 1990 ל-2040.
